Founder feedback verbatim: "the backtest run is not very informative." This ticket extended ONLY `apps/web/lib/ta/backtest.ts` + `lib/ta/selfcheck.ts` — additive fields on `BacktestStats`/`BacktestTrade`, zero touch to `strategy-panel.tsx`/`chart-workbench.tsx`/`script-editor-drawer.tsx`/`workbench/user-scripts/` (a concurrent drawer-UX sprint owns those). `strategies.ts` also untouched — `StrategyCandle` already carried `high`/`low` via `OhlcvLike`, no shared type needed there. ta:check 195→514 (4 new dedicated fixtures + ~90 new assertions on the existing fixture 1, plus generic finiteness sweeps over every numeric stat per fixture).

**Design laws established (documented in `backtest.ts`'s own module doc — read there for the full reasoning, this is the summary for planning the follow-on UI ticket):**

- SIGN LAW: every ₹ P&L stays naturally signed (a loss is negative) — `grossLoss`/`netLoss`/`avgLossGross|Net`/`largestLossGross|Net` are all `≤0`, matching pre-existing `BacktestTrade.grossPnl`/`netPnl`. Only pure ratios (`profitFactorGross|Net`, `avgWinLossRatioGross|Net`) are positive magnitudes. Matches TradingView's own display convention (checked against real knowledge of their Performance Summary).
- NULL LAW: every divide-by-zero-prone stat returns `null`, never `Infinity`/`NaN` — profit factor null only when zero LOSSES exist (zero wins + a loss still gives a real `0`, not null).
- OPEN-TRADE LAW: win/loss-classified aggregates (profit factor, expectancy, avg/largest win-loss, consecutive streaks, `grossWins`) are CLOSED-trades-only (matches pre-existing `wins`/`winRatePct` precedent). `avgTradeGrossPnl`/`avgTradeNetPnl`, time-in-market, equity curve, drawdown/run-up, and annualized return all INCLUDE the open trade's mark-to-last-close. Deliberate split: `avgTradeNetPnl === expectancyNet` exactly whenever there's no open trade (asserted as an equality invariant in the 3-trade fixture) — legitimately diverges when a trade is open.
- Annualization honesty gate: CAGR off `(1+returnPct/100)^(365.25/spanDays)-1`, `spanDays` = ACTUAL ELAPSED CALENDAR TIME between first/last candle timestamps (never bar count). Returns `null` under a 90-calendar-day floor (~1 quarter) — chosen because the workbench's default `1d` window is 5 years of daily bars (comfortably clears it) while short intraday windows correctly null out. This 90-day threshold is a CTO judgment call, not founder-specified — flag if the UI ticket or founder wants it tunable/surfaced.
- Drawdown ₹ (`maxDrawdownAmount`) and % (`maxDrawdownPct`) are computed as two INDEPENDENT running-peak maxima in the same pass — they deliberately do NOT always share a bar (an early small peak can give a big % dip that's small in ₹; a later huge peak gives a small % but big ₹ dip). Verified with a purpose-built fixture (`checkDrawdownShapeDivergence`) asserting the two maxima land on different bar indices. No "gross" variant of drawdown/run-up exists — costs are real cash flows, so only the net equity curve is an actual economic curve (documented as a deliberate scope line, not an oversight).
- MAE/MFE per trade: scans bars `entryIndex+1..exitIndex` (entry bar's own high/low excluded — fill happens at that bar's close, so the position was never exposed to that bar's intrabar range before it existed). GROSS or ₹ magnitude, floored at 0.

**Equity curve shape for the UI ticket** — `BacktestStats.equityCurve: EquityPoint[]`, one point per candle:
`{ timestamp, equity, drawdownPct, drawdownAmount, buyHoldEquity }`. `buyHoldEquity` is folded into the SAME point object (not a parallel array) so the UI can zip through one array for both series — deliberate choice, flagged as a design decision the UI ticket should know about (not the ticket's literal minimal shape, which only asked for `{timestamp,equity,drawdownPct}` — this is a superset).

**Known gap, flagged not hidden**: no fixture exercises a trade where GROSS classification (win/loss) differs from NET classification (a tiny gross win entirely eaten by costs, flipping to a net loss) — the 3-trade fixture's WIN/WIN/LOSS pattern holds on both gross and net sides by design margin (verified via an explicit `netPnl2 > 0` assertion, not assumed). Would need an artificially tiny-margin trade to construct; deferred as out of the ticket's 4 explicitly-required fixtures.

Full field list, exact per-field doc comments, and the 4 new fixtures (`checkThreeTradeKnownSeries`, `checkNoLossSeries`, `checkAnnualizedReturnPositiveCase`, `checkDrawdownShapeDivergence`) live in `apps/web/lib/ta/backtest.ts` and `apps/web/lib/ta/selfcheck.ts` directly — read those for anything this summary doesn't cover, don't trust this memory's specifics to stay in sync with the code.
